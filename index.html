CASE
01

FINTECH × PAYMENT

跨境匯款 × 全家 EC 繳費 × AML

當支付不是只有「串 API」，真正難的是交易狀態、條碼、銷帳、AML 與第三方平台之間要能一致。

CLIENT / 美家人力

問題：移工支付流程不順，跨系統狀態又容易失真

服務東南亞移工的跨境匯款流程，原本受限於既有第三方支付。真正的難點不是單一付款介面，而是全家 EC 給號、POS、AML 與銷帳 Callback之間的狀態必須一致。

SOLUTION

解法：把交易狀態變成一條可驗證的資料流

整合便利商店代碼繳費與條碼流程，建立 Callback、自動銷案與 POS 對帳邏輯，並針對條碼失效、回傳失敗與高交易量情境處理例外。

FOCUS

API 串接、AML、銷帳、自動回傳

SCALE

單一客戶月交易量約萬筆等級

CASE
02

TRAVEL × DISTRIBUTION

賞鯨訂位 × 同業分銷 × 後台效能

旅遊業的問題不只在前台訂票，而是不同經銷商、價格、航班、接送與報表怎麼一起運作。

CLIENT / 多羅滿賞鯨

問題：同業訂票人工化，統計與後台容易卡住

合作旅行社與同業沒有獨立追蹤方式，訂位、接送、伴手禮與統計分散；報表運算也容易造成 PHP 程序阻塞。

SOLUTION

解法：把分銷關係與營運流程放進同一套系統

建立 A/B/C 級同業、專屬分銷網址與 QR Code，串接航班訂位、購物車與接送設定，同時重構後台程序，降低報表造成的系統阻塞。

FOCUS

分銷、訂位、統計、伺服器流程

CASE
03

AI × KNOWLEDGE

LINE 對話 × 摘要 × 企業知識庫

聊天很多不代表資訊很多。真正要做的是把訊息變成可追蹤、可搜尋、可再利用的知識。

PROBLEM

問題：群組訊息過多，重點與待辦容易被洗掉

日常溝通存在 LINE 群組裡，決策、待辦與重要資訊高度依賴人工回找。

SOLUTION

解法：讓對話自動沉澱成結構化資訊

設計 LINE Chat Bot 蒐集對話，進行雜訊過濾、關鍵字擷取與活躍度分析，並自動產生日／週摘要，可匯入企業知識庫。

OUTPUT

PDF / Excel 摘要、關鍵資訊、知識沉澱

CASE
04

LINE × BOOKING × WORKFLOW

LINE 場地預約：不是做一張表單，
而是把整段人工協調拿掉。

使用者真正的問題不是「沒有預約頁面」，而是詢問空檔、核對場地、登記、避免撞期、通知與後續管理，全都需要人一直確認。

PROBLEM / 從現場問題開始

問題：每一次預約，都在消耗管理者的時間

傳統場地預約常變成一連串人工對話：「哪天有空？」→「可以訂多久？」→「這時段有人了嗎？」→「幫我登記」→「記得提醒我」。真正要解的不是表單，而是這整條反覆確認的工作流程。

PAIN POINT

人工查空檔、時段衝突、重複登記、提醒與資料整理

THINKING / 問題解決師視角

先拆流程，再決定 LINE、LIFF 與資料庫放在哪裡

把預約拆成「身份 → 場地 → 日期 → 可用時段 → 建立預約 → 通知 → 提醒 → 管理」，再把營業時間、場地規則、例外日與衝突檢查交給系統判斷。工具不是起點，流程才是。

SOLUTION / 把流程接起來

解法：讓使用者在 LINE 裡完成預約，讓系統處理後面的事

透過 LINE Webhook 與 LIFF 串接使用者流程，由時段引擎計算可預約區間，Cloudflare D1 保存會員、場地與預約狀態；完成後再進入通知、排程提醒、取消／延長與後台管理。

FLOW

LINE → LIFF → 選場地 → 選日期／時段 → 預約 → D1 → 通知／提醒

STACK

Cloudflare Workers · Hono · D1 · LINE Messaging API · LIFF

RESULT / 真正被解掉的問題

成果不是「多一套系統」，而是少掉一段人工工作

系統可以處理可用時段、衝突判斷、例外日期、預約狀態、排程提醒、取消與延長；管理端也能查詢、管理與匯出資料，延長操作保留稽核紀錄。管理者不必再當人工轉接站。

VALUE

降低重複確認，把預約規則標準化，讓服務可以持續運作

WHAT THESE CASES HAVE IN COMMON

看起來是不同產業，
其實一直在解同一種問題。

從 20 年前到現在，工具變很多，但專案底層一直重複出現同樣幾件事。

01

資料分散

資訊散在不同系統、表單、對話與人腦裡。

02

流程斷裂

每一步都能做，但中間要靠人手動搬運。

03

狀態不一致

支付、訂單、會員與後台對不上，問題難追。

04

重複人工

人一直在做核對、輸入、提醒、轉貼與追蹤。

05

系統彼此不說話

工具很多，但沒有 API、Webhook 或流程把它們接起來。

06

真正的解法

先拆問題，再決定 AI、自動化、API 與資料系統該放哪裡。
